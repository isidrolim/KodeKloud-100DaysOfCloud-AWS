# 100 Days of Cloud AWS - Day 015: Create Volume Snapshot

## Scenario

The Nautilus DevOps team is preparing automated backup processes for important AWS data.

As part of this preparation, a snapshot needs to be created from an existing Amazon EBS volume. EBS snapshots provide point-in-time backups that can later be used to restore data or create new EBS volumes.

## Requirement

Create an EBS snapshot with the following configuration:

- **Source Volume:** `xfusion-vol`
- **Snapshot Name:** `xfusion-vol-ss`
- **Description:** `xfusion Snapshot`
- **Region:** `us-east-1`
- **Final Snapshot Status:** `Completed`

## Implementation

### Step 1: Open the EC2 Console

1. Sign in to the **AWS Management Console**.
2. Make sure the selected region is:

```text
N. Virginia (us-east-1)
```

3. Search for and open **EC2**.
4. From the navigation pane, go to:

```text
Elastic Block Store → Volumes
```

### Step 2: Locate the Source Volume

Locate the existing EBS volume named:

```text
xfusion-vol
```

Select the volume and verify that it is the correct source before creating the snapshot.

Review:

```text
Volume Name
Volume ID
Volume Type
Size
Availability Zone
State
```

> In production, always verify the correct volume and understand which application or filesystem depends on it before creating or restoring snapshots.

### Step 3: Create the Snapshot

With `xfusion-vol` selected:

1. Click **Actions**.
2. Select **Create snapshot**.
3. Enter the required description:

```text
xfusion Snapshot
```

4. Under **Tags**, add:

```text
Key:   Name
Value: xfusion-vol-ss
```

5. Review the configuration.
6. Click **Create snapshot**.

## Validation

Navigate to:

```text
EC2 → Elastic Block Store → Snapshots
```

Select **Owned by me** if necessary.

Locate the snapshot named:

```text
xfusion-vol-ss
```

The snapshot may initially have the status:

```text
Pending
```

Wait for the snapshot operation to complete.

Do **not** submit the challenge until the status becomes:

```text
Completed
```

Verify the final configuration:

```text
Snapshot Name:  xfusion-vol-ss
Description:    xfusion Snapshot
Source Volume:  xfusion-vol
Status:         Completed
Region:         us-east-1
```

## Result

✅ Existing EBS volume `xfusion-vol` identified.

✅ Snapshot created from the correct source volume.

✅ Snapshot named `xfusion-vol-ss`.

✅ Description configured as `xfusion Snapshot`.

✅ Snapshot status verified as `Completed`.

✅ Challenge successfully completed and validated.

## Key Takeaway

An **EBS snapshot** is a point-in-time backup of an Amazon EBS volume.

The basic relationship is:

```text
EBS Volume
    │
    │ Create Snapshot
    ▼
EBS Snapshot
    │
    ├── Backup / Recovery
    │
    └── Create New EBS Volume
              │
              ▼
          EC2 Instance
```

EBS snapshots are **incremental** after the initial snapshot, meaning subsequent snapshots store the blocks that have changed since previous snapshots rather than requiring a completely independent copy of every block each time.

Also remember:

```text
EBS Volume  → Availability Zone resource
EBS Snapshot → Regional resource
```

Because a snapshot is regional, it can be used to create new EBS volumes in different Availability Zones within the same region.

In production, snapshots should be part of a broader backup strategy that considers **application consistency, retention policies, encryption, recovery testing, lifecycle management, and automated backups**.
