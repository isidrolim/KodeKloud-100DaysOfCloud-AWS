# 100 Days of Cloud AWS - Day 012: Attach Volume to EC2 Instance

## Scenario

The Nautilus DevOps team has an existing EC2 instance and an existing EBS volume in AWS.

For this task, the EBS volume must be attached to the EC2 instance using the required device name.

## Requirement

Attach the existing EBS volume with the following configuration:

- **EC2 Instance:** `nautilus-ec2`
- **EBS Volume:** `nautilus-volume`
- **Device Name:** `/dev/sdb`
- **Region:** `us-east-1`

## Implementation

### Step 1: Open the EC2 Console

1. Sign in to the **AWS Management Console**.
2. Make sure the selected region is:

```text
N. Virginia (us-east-1)
```

3. Search for and open **EC2**.

### Step 2: Verify the EC2 Instance

Navigate to:

```text
Instances → Instances
```

Locate:

```text
nautilus-ec2
```

Check the instance details and note its **Availability Zone**.

For example:

```text
us-east-1a
```

### Step 3: Locate the EBS Volume

From the EC2 navigation pane, go to:

```text
Elastic Block Store → Volumes
```

Locate and select:

```text
nautilus-volume
```

Before attaching the volume, verify:

- The volume state is `Available`.
- The volume is not already attached to another instance.
- The volume is in the **same Availability Zone** as `nautilus-ec2`.

> An EBS volume can only be directly attached to an EC2 instance located in the same Availability Zone.

### Step 4: Attach the Volume

With `nautilus-volume` selected:

1. Click **Actions**.
2. Select **Attach volume**.
3. Under **Instance**, select:

```text
nautilus-ec2
```

4. For **Device name**, enter:

```text
/dev/sdb
```

5. Review the configuration.
6. Click **Attach volume**.

### Step 5: Verify the Attachment

Return to:

```text
EC2 → Elastic Block Store → Volumes
```

Select `nautilus-volume`.

Verify that the volume state has changed from:

```text
Available
```

to:

```text
In-use
```

Check the attachment information and confirm:

```text
Instance:     nautilus-ec2
Device Name:  /dev/sdb
```

## Validation

The final configuration should show:

```text
EBS Volume:       nautilus-volume
Volume State:     In-use
EC2 Instance:     nautilus-ec2
Device Name:      /dev/sdb
Region:           us-east-1
Availability Zone: Same for EC2 and EBS
```

The storage dependency now looks like:

```text
nautilus-volume
      │
      │ /dev/sdb
      ▼
 nautilus-ec2
```

## Result

✅ Existing EC2 instance `nautilus-ec2` identified.

✅ Existing EBS volume `nautilus-volume` identified.

✅ EC2 instance and EBS volume verified to be in the same Availability Zone.

✅ EBS volume attached using device name `/dev/sdb`.

✅ Volume status verified as `In-use`.

✅ Challenge successfully completed and validated.

## Key Takeaway

An **EBS volume** provides persistent block storage that can be attached to an EC2 instance.

A critical dependency when attaching EBS storage is:

```text
EC2 Availability Zone == EBS Availability Zone
```

The volume and instance must reside in the **same Availability Zone** for the attachment to succeed.

Also remember that:

```text
AWS Attachment
      ↓
Block Device Visible to OS
      ↓
Partition / Filesystem
      ↓
Mount Point
      ↓
Application Storage
```

Attaching an EBS volume in AWS only makes the block device available to the operating system. In a real Linux server, additional steps may still be required to identify the device, create a partition if needed, create a filesystem, mount it, and configure `/etc/fstab` for persistence.

> **Note:** On some EC2 instance types, especially Nitro-based instances, a volume requested as `/dev/sdb` in AWS may appear inside Linux with an NVMe device name such as `/dev/nvme1n1`. Always verify the actual block device from the operating system before formatting or mounting it.
