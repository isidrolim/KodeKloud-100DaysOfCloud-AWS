# 100 Days of Cloud AWS - Day 010: Attach Elastic IP to EC2 Instance

## Scenario

The Nautilus DevOps team has been deploying AWS resources as part of an incremental cloud migration.

For this task, an existing Elastic IP address needs to be associated with an existing EC2 instance to provide it with a persistent public IPv4 address.

## Requirement

Associate the existing Elastic IP with the existing EC2 instance:

- **EC2 Instance:** `datacenter-ec2`
- **Elastic IP Name:** `datacenter-ec2-eip`
- **Region:** `us-east-1`

## Implementation

### Step 1: Open the EC2 Console

1. Sign in to the **AWS Management Console**.
2. Make sure the selected region is:

```text
N. Virginia (us-east-1)
```

3. Search for and open **EC2**.

### Step 2: Verify the EC2 Instance

Navigate to:

```text
Instances → Instances
```

Locate:

```text
datacenter-ec2
```

Confirm that this is the correct instance before making any network changes.

### Step 3: Locate the Elastic IP

From the EC2 navigation pane, go to:

```text
Network & Security → Elastic IPs
```

Locate the Elastic IP named:

```text
datacenter-ec2-eip
```

Verify that the Elastic IP is currently available and not associated with another resource.

### Step 4: Associate the Elastic IP

1. Select `datacenter-ec2-eip`.
2. Click **Actions**.
3. Select **Associate Elastic IP address**.
4. For **Resource type**, select:

```text
Instance
```

5. Under **Instance**, select:

```text
datacenter-ec2
```

6. Select the appropriate private IP address if AWS asks for one.
7. Click **Associate**.

## Validation

Return to:

```text
EC2 → Instances → datacenter-ec2
```

Verify that the instance now displays the Elastic IP as its public IPv4 address.

Also check:

```text
EC2 → Network & Security → Elastic IPs
```

Select `datacenter-ec2-eip` and confirm that it is associated with:

```text
datacenter-ec2
```

Final configuration:

```text
EC2 Instance:     datacenter-ec2
Elastic IP Name:  datacenter-ec2-eip
Association:      Attached
Region:           us-east-1
```

## Result

✅ Existing EC2 instance `datacenter-ec2` identified.

✅ Existing Elastic IP `datacenter-ec2-eip` identified.

✅ Elastic IP successfully associated with the EC2 instance.

✅ Association verified from the AWS Console.

✅ Challenge successfully completed and validated.

## Key Takeaway

A normal EC2 public IPv4 address can change after certain instance lifecycle operations, while an **Elastic IP (EIP)** is a static public IPv4 address allocated to your AWS account.

The relationship can be visualized as:

```text
Internet
   │
   ▼
Elastic IP
   │
   ▼
EC2 Network Interface
   │
   ▼
Private IP
   │
   ▼
EC2 Instance
```

An Elastic IP provides a stable public address that can be reassociated with another compatible resource when necessary.

In production, Elastic IPs should be allocated intentionally because public IPv4 addresses have associated AWS charges, and exposing an instance publicly should always be evaluated alongside its security groups, routing, and actual connectivity requirements.
