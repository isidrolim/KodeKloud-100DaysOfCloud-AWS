# 100 Days of Cloud AWS - Day 025: Setting Up an EC2 Instance and CloudWatch Alarm

## Scenario

The Nautilus DevOps team needs to deploy an EC2 instance for an application and configure monitoring for high CPU utilization.

An Amazon CloudWatch alarm will monitor the instance's CPU utilization and send a notification through an existing Amazon SNS topic whenever CPU usage reaches the configured threshold.

## Requirement

Configure the following AWS resources:

### EC2 Instance

- **Instance Name:** `nautilus-ec2`
- **AMI:** Any appropriate Ubuntu AMI
- **Region:** `us-east-1`

### CloudWatch Alarm

- **Alarm Name:** `nautilus-alarm`
- **Metric:** `CPUUtilization`
- **Statistic:** `Average`
- **Threshold:** Greater than or equal to `90%`
- **Period:** `5 minutes`
- **Evaluation Periods:** `1`
- **Datapoints to Alarm:** `1 out of 1`
- **SNS Topic:** `nautilus-sns-topic`

The intended monitoring flow is:

```text
nautilus-ec2
     │
     │ CPUUtilization
     ▼
Amazon CloudWatch
     │
     │ >= 90% for one 5-minute period
     ▼
nautilus-alarm
     │
     ▼
nautilus-sns-topic
     │
     ▼
Notification
```

## Implementation

### Step 1: Launch the EC2 Instance

Open:

```text
AWS Console → EC2 → Instances → Launch instances
```

Under **Name and tags**, enter:

```text
nautilus-ec2
```

Under **Application and OS Images**, select an appropriate:

```text
Ubuntu Server AMI
```

Configure the remaining instance settings as appropriate for the lab.

Ensure the instance is created in:

```text
us-east-1
```

Click:

```text
Launch instance
```

### Step 2: Verify the EC2 Instance

Navigate to:

```text
EC2 → Instances
```

Locate:

```text
nautilus-ec2
```

Verify that the instance reaches:

```text
Instance state: Running
```

Ideally, wait until the status checks show:

```text
2/2 checks passed
```

### Step 3: Open CloudWatch

Search for:

```text
CloudWatch
```

Navigate to:

```text
CloudWatch → Alarms → All alarms
```

Click:

```text
Create alarm
```

### Step 4: Select the CPU Metric

Click:

```text
Select metric
```

Navigate through:

```text
EC2
  ↓
Per-Instance Metrics
```

Locate the instance ID belonging to:

```text
nautilus-ec2
```

Select:

```text
CPUUtilization
```

Click:

```text
Select metric
```

### Step 5: Configure the Metric

Configure:

```text
Metric name: CPUUtilization
Statistic:   Average
Period:      5 minutes
```

This means CloudWatch evaluates the average CPU utilization over each five-minute period.

### Step 6: Configure the Alarm Condition

Under **Conditions**, configure:

```text
Threshold type:
Static
```

Select:

```text
Greater/Equal
```

Set the threshold value to:

```text
90
```

The condition becomes:

```text
CPUUtilization >= 90%
```

### Step 7: Configure Evaluation

Configure the alarm to trigger after one consecutive five-minute period.

Use:

```text
Evaluation periods:  1
Datapoints to alarm: 1
```

The logic becomes:

```text
5-minute CPU average
        │
        ▼
Is CPU >= 90%?
    │        │
   No       Yes
    │        │
    ▼        ▼
   OK      ALARM
```

### Step 8: Configure the SNS Notification

Under **Notification**, configure the action for:

```text
In alarm
```

Select:

```text
Select an existing SNS topic
```

Choose:

```text
nautilus-sns-topic
```

This creates the notification path:

```text
CloudWatch Alarm
      │
      │ State = ALARM
      ▼
nautilus-sns-topic
      │
      ▼
SNS Notification
```

### Step 9: Configure the Alarm Name

Enter:

```text
nautilus-alarm
```

Review the complete configuration:

```text
Alarm:              nautilus-alarm
Metric:             CPUUtilization
Statistic:          Average
Period:             5 minutes
Threshold:          >= 90%
Evaluation periods: 1
Datapoints to alarm: 1 of 1
Notification:       nautilus-sns-topic
```

Click:

```text
Create alarm
```

## Key Takeaway

CloudWatch separates **monitoring** from **notification**:

```text
EC2
 │
 │ produces metric
 ▼
CloudWatch Metric
CPUUtilization
 │
 │ evaluated against threshold
 ▼
CloudWatch Alarm
nautilus-alarm
 │
 │ enters ALARM state
 ▼
SNS
nautilus-sns-topic
 │
 ▼
Notification
```

The important components have different responsibilities:

```text
Metric
└── What are we measuring?

Statistic
└── How is the metric summarized?

Period
└── Over what time window?

Threshold
└── What value represents a problem?

Evaluation Period
└── How long must the condition be satisfied?

Alarm Action
└── What happens when the alarm triggers?
```

For this challenge:

```text
CPUUtilization
      ↓
Average over 5 minutes
      ↓
>= 90%
      ↓
1 consecutive period
      ↓
ALARM
      ↓
nautilus-sns-topic
```

A CloudWatch alarm does not continuously inspect the operating system itself. It evaluates the metric data published to CloudWatch and changes state according to the configured threshold and evaluation criteria.

In production, alert thresholds should be based on normal workload behavior and operational impact rather than choosing arbitrary values. A high CPU alarm becomes most useful when it produces an actionable notification that helps engineers identify and respond to a genuine performance issue.
