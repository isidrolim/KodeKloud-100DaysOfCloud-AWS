# 100 Days of Cloud AWS - Day 013: Create AMI from EC2 Instance

## Scenario

The Nautilus DevOps team is continuing its incremental migration to AWS.

For this task, an **Amazon Machine Image (AMI)** must be created from an existing EC2 instance. The AMI can later be used to launch new EC2 instances based on the captured server configuration.

## Requirement

Create an AMI with the following configuration:

- **Source EC2 Instance:** `devops-ec2`
- **AMI Name:** `devops-ec2-ami`
- **Region:** `us-east-1`
- **Final AMI State:** `Available`

## Implementation

### Step 1: Open the EC2 Console

1. Sign in to the **AWS Management Console**.
2. Make sure the selected region is:

```text
N. Virginia (us-east-1)
```

3. Search for and open **EC2**.
4. Navigate to:

```text
Instances → Instances
```

### Step 2: Locate the Source Instance

Locate and select:

```text
devops-ec2
```

Before creating the image, verify that you selected the correct instance.

Review important details such as:

```text
Instance Name
Instance ID
Instance State
Attached EBS Volumes
```

### Step 3: Create the AMI

With `devops-ec2` selected:

1. Click **Actions**.
2. Navigate to:

```text
Image and templates → Create image
```

3. Enter the image name:

```text
devops-ec2-ami
```

4. Leave the other settings at their defaults unless required by the challenge.
5. Review the attached volume configuration.
6. Click **Create image**.

> By default, AWS may reboot the instance during AMI creation to help produce a consistent image. In production, the impact of this reboot should be evaluated before creating the AMI.

### Step 4: Monitor AMI Creation

Navigate to:

```text
EC2 → Images → AMIs
```

Select:

```text
Owned by me
```

Locate:

```text
devops-ec2-ami
```

The AMI may initially show:

```text
Pending
```

Do not submit the challenge yet.

Wait until the AMI state changes to:

```text
Available
```

## Validation

Verify the final configuration:

```text
AMI Name:         devops-ec2-ami
Source Instance:  devops-ec2
AMI State:        Available
Region:           us-east-1
```

The AMI creation process can be visualized as:

```text
devops-ec2
     │
     │ Create Image
     ▼
EBS Snapshots
     │
     ▼
devops-ec2-ami
     │
     ▼
   Available
```

The original success criteria are satisfied once:

- `devops-ec2-ami` exists.
- The AMI was created from `devops-ec2`.
- The AMI state is `Available`.

## Result

✅ Existing EC2 instance `devops-ec2` identified.

✅ AMI `devops-ec2-ami` successfully created.

✅ Associated EBS snapshots created as part of the image process.

✅ AMI state verified as `Available`.

✅ Challenge successfully completed and validated.

## Key Takeaway

An **Amazon Machine Image (AMI)** is a reusable template that contains the information required to launch EC2 instances.

The relationship is:

```text
EC2 Instance
     │
     ▼
Create AMI
     │
     ├── Instance configuration
     │
     └── EBS snapshots
              │
              ▼
             AMI
              │
              ▼
       New EC2 Instances
```

Creating an AMI does **not** simply copy a running virtual machine as one file. For EBS-backed instances, AWS creates snapshots of the relevant EBS volumes and registers an AMI that references the required image and block-device information.

In production, always consider **application consistency, reboot impact, attached volumes, encryption, snapshot lifecycle, and AMI cleanup** before using AMIs as part of a backup or deployment strategy.
