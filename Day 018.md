# 100 Days of Cloud AWS - Day 018: Create Read-Only IAM Policy for EC2 Console Access

## Scenario

The Nautilus DevOps team is continuing to configure AWS Identity and Access Management (IAM) as part of its cloud migration.

For this task, a custom IAM policy must be created that provides **read-only access to Amazon EC2 resources**, allowing users to view EC2 instances, AMIs, snapshots, and other information available through the Amazon EC2 console without granting permission to modify resources.

## Requirement

Create an IAM policy with the following configuration:

- **Policy Name:** `iampolicy_siva`
- **Access Level:** Read-only
- **Service:** Amazon EC2
- Allow users to view:
  - EC2 instances
  - AMIs
  - EBS volumes
  - EBS snapshots
  - Security groups
  - Network interfaces
  - Other EC2 resources
- Do not grant permissions to create, modify, stop, terminate, or delete EC2 resources.

## Implementation

### Step 1: Open the IAM Console

1. Sign in to the **AWS Management Console**.
2. Search for:

```text
IAM
```

3. Open **Identity and Access Management (IAM)**.
4. Navigate to:

```text
Access management → Policies
```

5. Click:

```text
Create policy
```

### Step 2: Use the JSON Policy Editor

Select the **JSON** policy editor.

Enter the following policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ec2:Describe*",
      "Resource": "*"
    }
  ]
}
```

### Step 3: Understand the Policy

The key permission is:

```text
ec2:Describe*
```

This allows EC2 read operations such as:

```text
DescribeInstances
DescribeImages
DescribeVolumes
DescribeSnapshots
DescribeSecurityGroups
DescribeNetworkInterfaces
```

The policy does not grant write operations such as:

```text
RunInstances
TerminateInstances
StopInstances
CreateVolume
DeleteVolume
CreateSnapshot
DeleteSnapshot
```

The resource is configured as:

```json
"Resource": "*"
```

because EC2 `Describe` operations generally require access across resources for listing and viewing EC2 information.

### Step 4: Create the Policy

1. Click **Next**.
2. Enter the policy name:

```text
iampolicy_siva
```

3. Optionally enter a description such as:

```text
Read-only access to Amazon EC2 resources
```

4. Review the permissions.
5. Click:

```text
Create policy
```

## Validation

Navigate to:

```text
IAM → Policies
```

Search for:

```text
iampolicy_siva
```

Open the policy and verify the permissions contain:

```json
{
  "Effect": "Allow",
  "Action": "ec2:Describe*",
  "Resource": "*"
}
```

Confirm that the policy does not contain EC2 modification permissions.

Final configuration:

```text
Policy Name:  iampolicy_siva
Service:      Amazon EC2
Access:       Read-only
Actions:      ec2:Describe*
Resource:     *
```

## Result

✅ Custom IAM policy `iampolicy_siva` created.

✅ Read-only EC2 permissions configured.

✅ Users assigned this policy can view EC2 instances, AMIs, snapshots, volumes, and other EC2 information.

✅ No EC2 create, modify, stop, terminate, or delete permissions granted.

✅ Challenge successfully completed and validated.

## Key Takeaway

IAM policies define what actions an identity is allowed or denied to perform against AWS resources.

The policy created in this challenge follows this authorization path:

```text
IAM User / Role / Group
          │
          ▼
   iampolicy_siva
          │
          ▼
    ec2:Describe*
          │
          ▼
   EC2 Read Access
          │
     ┌────┼─────┐
     ▼    ▼     ▼
 Instances AMIs Snapshots
 Volumes   ENIs Security Groups
```

The important distinction is:

```text
Describe / List / Get
        │
        ▼
     READ

Create / Modify / Delete
        │
        ▼
     WRITE
```

Using read-only permissions is an example of applying the **principle of least privilege**. Users who only need to inspect infrastructure should not receive permissions capable of modifying or deleting it.

In production, prefer granting policies to **roles or groups** rather than repeatedly attaching permissions directly to individual users, and periodically review permissions to ensure they still match operational requirements.
