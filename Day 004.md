# 100 Days of Cloud AWS - Day 004: Enable S3 Bucket Versioning via AWS CLI

## Scenario

The Nautilus DevOps team needs to improve data protection and recovery for an existing Amazon S3 bucket. Enabling versioning allows previous versions of objects to be retained when objects are modified or deleted.

## Requirement

Enable versioning on the following S3 bucket:

- **Bucket Name:** `nautilus-s3-79`
- **Versioning:** Enabled
- **Region:** `us-east-1`

## Implementation

First, verify that the S3 bucket exists:

```bash
aws s3api head-bucket \
  --bucket nautilus-s3-79
```

Enable versioning:

```bash
aws s3api put-bucket-versioning \
  --bucket nautilus-s3-79 \
  --versioning-configuration Status=Enabled
```

## Validation

Check the bucket's versioning status:

```bash
aws s3api get-bucket-versioning \
  --bucket nautilus-s3-79
```

Expected output:

```json
{
    "Status": "Enabled"
}
```

## Result

✅ S3 bucket `nautilus-s3-79` identified.

✅ Bucket versioning successfully enabled.

✅ Versioning status verified as `Enabled`.

✅ Challenge successfully completed and validated.

## Key Takeaway

S3 Versioning protects against accidental overwrites and deletions by preserving multiple versions of an object.

When a versioned object is deleted, S3 normally adds a **delete marker** rather than permanently removing all existing versions. This makes recovery of accidentally deleted objects possible.
