# 100 Days of Cloud AWS - Day 017: Create IAM Group

## Scenario

The Nautilus DevOps team is continuing to configure AWS Identity and Access Management (IAM) resources as part of its cloud migration.

For this task, an **IAM user group** needs to be created. IAM groups provide a convenient way to manage permissions for multiple IAM users that require the same level of access.

## Requirement

Create an IAM group with the following configuration:

- **IAM Group Name:** `iamgroup_john`
- No IAM policies need to be attached unless specifically required by the task.
- No IAM users need to be added to the group for this task.

## Implementation

### Step 1: Open the IAM Console

1. Sign in to the **AWS Management Console**.
2. Search for:

```text
IAM
```

3. Open **Identity and Access Management (IAM)**.

> IAM is a global AWS service, so IAM groups are not tied to a specific AWS Region.

### Step 2: Navigate to User Groups

From the IAM navigation pane, select:

```text
Access management → User groups
```

Click:

```text
Create group
```

### Step 3: Configure the Group

Enter the required group name:

```text
iamgroup_john
```

For this challenge, only the IAM group itself is required.

Do not add users or attach policies unless specifically requested.

### Step 4: Create the Group

Review the configuration:

```text
Group name: iamgroup_john
```

Click:

```text
Create group
```

## Validation

Navigate to:

```text
IAM → User groups
```

Verify that the following group exists:

```text
iamgroup_john
```

Select the group and confirm:

```text
Group name: iamgroup_john
```

Since no additional configuration was required, the challenge is complete once the IAM group exists.

## Result

✅ IAM group `iamgroup_john` created successfully.

✅ No unnecessary IAM policies were attached.

✅ No users were added because the task did not require membership configuration.

✅ Group existence verified from the IAM console.

✅ Challenge successfully completed and validated.

## Key Takeaway

An **IAM user group** allows permissions to be managed for multiple IAM users collectively rather than configuring identical permissions for each user individually.

The relationship can be visualized as:

```text
IAM Policy
     │
     ▼
IAM User Group
     │
     ├── IAM User A
     ├── IAM User B
     └── IAM User C
```

For example, instead of attaching the same policy separately to several administrators:

```text
Policy → User A
Policy → User B
Policy → User C
```

the users can be placed into a group:

```text
        Policy
          │
          ▼
    Admins Group
      /   |   \
     ▼    ▼    ▼
 User A User B User C
```

This simplifies permission management and helps maintain consistent access across users with similar responsibilities.

A key production principle remains **least privilege**:

```text
Job Requirement
      ↓
Required Permissions
      ↓
IAM Policy
      ↓
IAM Group
      ↓
IAM Users
```

Users should only receive the permissions required to perform their responsibilities, and group membership should be reviewed regularly as roles and responsibilities change.
