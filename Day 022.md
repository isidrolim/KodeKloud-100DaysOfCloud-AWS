# 100 Days of Cloud AWS - Day 022: Configuring Secure SSH Access to an EC2 Instance

## Scenario

The Nautilus DevOps team needs to deploy a new EC2 instance that can be securely accessed from the `aws-client` landing host.

Instead of using password authentication, an SSH key pair must be generated on the `aws-client` host. The public key will then be installed on the EC2 instance to provide passwordless SSH access.

## Requirement

Configure the environment with the following requirements:

- **EC2 Instance Name:** `xfusion-ec2`
- **Instance Type:** `t2.micro`
- **Region:** `us-east-1`
- Create a new SSH key pair on `aws-client`.
- **Private Key:** `/root/.ssh/id_rsa`
- Add the corresponding public key to the EC2 instance.
- Configure the public key for the `root` user.
- Verify passwordless SSH access from `aws-client`.

## Implementation

### Step 1: Check for an Existing SSH Key

On the `aws-client` host, first check the SSH directory:

```bash
ls -la /root/.ssh/
```

The required key is:

```text
/root/.ssh/id_rsa
```

If it does not already exist, create a new RSA SSH key pair.

```bash
ssh-keygen -t rsa -f /root/.ssh/id_rsa
```

When prompted for a passphrase, press **Enter** if the lab requires passwordless authentication.

This creates:

```text
/root/.ssh/id_rsa      ← Private key
/root/.ssh/id_rsa.pub  ← Public key
```

> Never copy or expose `id_rsa`. Only the `.pub` file should be installed on the remote server.

### Step 2: Retrieve the Public Key

Display the public key:

```bash
cat /root/.ssh/id_rsa.pub
```

Copy the complete public key.

It will look similar to:

```text
ssh-rsa AAAA... root@aws-client
```

### Step 3: Launch the EC2 Instance

Open the AWS Management Console and navigate to:

```text
EC2 → Instances → Launch instances
```

Configure:

```text
Name:           xfusion-ec2
Instance Type:  t2.micro
Region:         us-east-1
AMI:            Linux
```

Select an appropriate VPC, subnet, and security group for the lab.

The security group must permit SSH traffic required for access from the `aws-client` host.

### Step 4: Install the Public Key

During instance creation, use the EC2 **Advanced details → User data** section to configure the required SSH key for `root`.

For example:

```bash
#!/bin/bash

mkdir -p /root/.ssh
chmod 700 /root/.ssh

echo 'PASTE_PUBLIC_KEY_HERE' >> /root/.ssh/authorized_keys

chmod 600 /root/.ssh/authorized_keys
```

Replace:

```text
PASTE_PUBLIC_KEY_HERE
```

with the contents of:

```text
/root/.ssh/id_rsa.pub
```

This establishes the authentication relationship:

```text
aws-client
/root/.ssh/id_rsa
      │
      │ SSH authentication
      ▼
xfusion-ec2
/root/.ssh/authorized_keys
```

### Step 5: Launch and Wait for Initialization

Launch the EC2 instance.

Navigate to:

```text
EC2 → Instances
```

Wait until `xfusion-ec2` shows:

```text
Instance State: Running
Status Checks:  2/2 checks passed
```

Note the instance's reachable IP address.

## Validation

From `aws-client`, test SSH access using the generated private key:

```bash
ssh -i /root/.ssh/id_rsa root@<EC2-IP>
```

The important success criterion is that authentication succeeds using the SSH key without requesting the remote user's password.

Once connected, verify:

```bash
whoami
```

Expected result:

```text
root
```

You can also verify the authorized key:

```bash
cat /root/.ssh/authorized_keys
```

The public key should correspond to:

```text
/root/.ssh/id_rsa.pub
```

on `aws-client`.

## Result

✅ EC2 instance `xfusion-ec2` created.

✅ Instance type configured as `t2.micro`.

✅ RSA SSH key pair generated under `/root/.ssh/`.

✅ Private key stored as `/root/.ssh/id_rsa`.

✅ Public key installed in the EC2 root user's `authorized_keys`.

✅ Passwordless SSH authentication from `aws-client` verified.

✅ Challenge successfully completed and validated.

## Key Takeaway

SSH public-key authentication uses two related but separate keys:

```text
aws-client
┌────────────────────────────┐
│ /root/.ssh/id_rsa          │
│ PRIVATE KEY                │
│ Keep secret                │
└──────────────┬─────────────┘
               │
               │ SSH authentication
               ▼
┌────────────────────────────┐
│ xfusion-ec2                │
│                            │
│ /root/.ssh/authorized_keys │
│ PUBLIC KEY                 │
└────────────────────────────┘
```

The fundamental rule is:

```text
Private Key → stays on the client
Public Key  → goes to the server
```

The private key should **never** be copied to the EC2 instance or committed to GitHub.

Also remember that successful SSH requires more than just the correct key:

```text
SSH Client
    ↓
Private Key
    ↓
Network Route
    ↓
Security Group TCP/22
    ↓
sshd
    ↓
authorized_keys
    ↓
Authentication Successful
```

If SSH fails, troubleshooting should follow this dependency path instead of immediately assuming the SSH key is the problem.
