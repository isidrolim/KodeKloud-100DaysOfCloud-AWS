# 100 Days of Cloud AWS - Day 011: Attach Elastic Network Interface to EC2 Instance

## Scenario

The Nautilus DevOps team has an existing EC2 instance and an existing Elastic Network Interface (ENI) in AWS.

For this task, the additional network interface must be attached to the EC2 instance and verified before completing the challenge.

## Requirement

Configure the existing resources with the following requirements:

- **EC2 Instance:** `nautilus-ec2`
- **Elastic Network Interface:** `nautilus-eni`
- **Region:** `us-east-1`
- **ENI Status After Change:** `Attached`
- Ensure the EC2 instance has completed initialization before submitting the task.

## Implementation

### Step 1: Open the EC2 Console

1. Sign in to the **AWS Management Console**.
2. Make sure the selected region is:

```text
N. Virginia (us-east-1)
```

3. Search for and open **EC2**.
4. Navigate to:

```text
Instances → Instances
```

### Step 2: Verify the EC2 Instance

Locate and select:

```text
nautilus-ec2
```

Before making the change, verify that the instance has completed initialization.

Confirm:

```text
Instance State: Running
Status Checks:  2/2 checks passed
```

Wait if the instance is still initializing.

### Step 3: Locate the Elastic Network Interface

From the EC2 navigation pane, go to:

```text
Network & Security → Network Interfaces
```

Locate:

```text
nautilus-eni
```

Before attaching it, verify:

- The ENI is currently available.
- The ENI is not already attached to another instance.
- The ENI is in the same Availability Zone as `nautilus-ec2`.

> An Elastic Network Interface can only be attached to an EC2 instance in the same Availability Zone.

### Step 4: Attach the ENI

1. Select `nautilus-eni`.
2. Click **Actions**.
3. Select **Attach** or **Attach network interface**.
4. Under **Instance**, select:

```text
nautilus-ec2
```

5. Review the selection.
6. Click **Attach**.

### Step 5: Wait for the Attachment

After attaching the network interface, remain on the **Network Interfaces** page or refresh the page.

Wait until the ENI status shows:

```text
In-use
```

and its attachment information references:

```text
nautilus-ec2
```

## Validation

### Validate from the Network Interface

Navigate to:

```text
EC2 → Network & Security → Network Interfaces
```

Select `nautilus-eni` and verify:

```text
Network Interface:  nautilus-eni
Status:             In-use
Attached Instance:  nautilus-ec2
Region:             us-east-1
```

### Validate from the EC2 Instance

Navigate to:

```text
EC2 → Instances → nautilus-ec2
```

Check the instance's **Networking** information and confirm that the additional network interface is attached.

The dependency relationship should now be:

```text
nautilus-ec2
     │
     ├── Primary ENI
     │
     └── nautilus-eni
            │
            └── Attached / In-use
```

## Result

✅ EC2 instance `nautilus-ec2` identified.

✅ Instance initialization completed before the change.

✅ Elastic Network Interface `nautilus-eni` identified.

✅ ENI successfully attached to `nautilus-ec2`.

✅ Network interface status verified as attached/in-use.

✅ Challenge successfully completed and validated.

## Key Takeaway

An **Elastic Network Interface (ENI)** is a virtual network interface that can be attached to an EC2 instance.

An ENI contains networking attributes such as:

```text
Private IP Address
        +
MAC Address
        +
Security Groups
        +
Optional Public/Elastic IP association
```

An EC2 instance always has a **primary network interface**, while supported instance types can also have additional secondary ENIs.

One critical dependency to remember is:

```text
EC2 Instance AZ == ENI AZ
```

If the EC2 instance and ENI are located in different Availability Zones, AWS will not allow the ENI to be attached. Verifying this dependency before attempting the change is safer than troubleshooting the attachment after it fails.
