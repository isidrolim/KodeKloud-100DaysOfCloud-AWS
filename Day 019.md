# 100 Days of Cloud AWS - Day 019: Attach IAM Policy to IAM User

## Scenario

The Nautilus DevOps team is continuing to configure AWS Identity and Access Management (IAM) resources as part of its cloud migration.

For this task, an existing IAM policy must be attached directly to an existing IAM user so that the user receives the permissions defined by that policy.

## Requirement

Configure the following existing IAM resources:

- **IAM User:** `iamuser_javed`
- **IAM Policy:** `iampolicy_javed`
- **Action:** Attach `iampolicy_javed` to `iamuser_javed`

No new IAM user or policy needs to be created.

## Implementation

### Step 1: Open the IAM Console

1. Sign in to the **AWS Management Console**.
2. Search for:

```text
IAM
```

3. Open **Identity and Access Management (IAM)**.

> IAM is a global AWS service, so IAM users and policies are not tied to an individual AWS Region.

### Step 2: Verify the Existing IAM User

Navigate to:

```text
IAM → Access management → Users
```

Locate:

```text
iamuser_javed
```

Confirm that the user already exists before making any changes.

### Step 3: Verify the Existing IAM Policy

Navigate to:

```text
IAM → Access management → Policies
```

Search for:

```text
iampolicy_javed
```

Verify that the policy exists.

Before attaching a policy in a production environment, its permissions should also be reviewed to understand exactly what access will be granted.

### Step 4: Attach the Policy to the User

Return to:

```text
IAM → Users → iamuser_javed
```

Open the **Permissions** tab.

Click:

```text
Add permissions
```

Choose:

```text
Attach policies directly
```

Search for:

```text
iampolicy_javed
```

Select the checkbox beside the policy and continue.

Review the configuration:

```text
IAM User:    iamuser_javed
IAM Policy:  iampolicy_javed
```

Click:

```text
Add permissions
```

## Validation

Navigate back to:

```text
IAM → Users → iamuser_javed → Permissions
```

Under **Permissions policies**, verify that the following policy is listed:

```text
iampolicy_javed
```

The final relationship should be:

```text
iamuser_javed
      │
      │ Attached Policy
      ▼
iampolicy_javed
      │
      ▼
Permissions defined
inside the policy
```

The original success criteria are satisfied when `iampolicy_javed` appears as an attached permissions policy for `iamuser_javed`.

## Result

✅ Existing IAM user `iamuser_javed` identified.

✅ Existing IAM policy `iampolicy_javed` identified.

✅ IAM policy successfully attached directly to the IAM user.

✅ Attachment verified from the user's **Permissions** tab.

✅ Challenge successfully completed and validated.

## Key Takeaway

An IAM policy contains permission statements, but those permissions do not affect a user until the policy is associated with an IAM identity.

The authorization path for this challenge is:

```text
IAM User
iamuser_javed
      │
      ▼
IAM Policy
iampolicy_javed
      │
      ▼
Allowed / Denied Actions
      │
      ▼
AWS Resources
```

Attaching a managed policy directly to a user is supported, but for larger environments it is often easier to manage permissions through groups or roles:

```text
        IAM Policy
             │
             ▼
        IAM Group
        /    |    \
       ▼     ▼     ▼
    User A User B User C
```

This allows users with the same job function to receive consistent permissions without maintaining identical policy attachments individually.

Regardless of the attachment method, always follow the **principle of least privilege**:

```text
Business Requirement
        ↓
Required Actions
        ↓
Minimum Permissions
        ↓
IAM Policy
        ↓
IAM Identity
```

Before attaching any policy in production, review what it actually permits rather than relying only on the policy name.
