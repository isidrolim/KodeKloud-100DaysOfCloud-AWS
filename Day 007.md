# 100 Days of Cloud AWS - Day 007: Change EC2 Instance Type

## Scenario

During the AWS migration, the Nautilus DevOps team identified an EC2 instance that was underutilized. To optimize resource usage, the instance needs to be resized to a smaller instance type.

## Requirement

Modify the existing EC2 instance with the following configuration:

- **Instance Name:** `datacenter-ec2`
- **Current Instance Type:** `t2.micro`
- **New Instance Type:** `t2.nano`
- **Region:** `us-east-1`
- Ensure the **status checks are completed** before making changes.
- Ensure the instance is returned to the **Running** state after the change.

## Implementation

### Step 1: Open the EC2 Console

1. Sign in to the **AWS Management Console**.
2. Make sure the selected region is **N. Virginia (`us-east-1`)**.
3. Open **EC2**.
4. Navigate to **Instances → Instances**.
5. Locate and select:

```text
datacenter-ec2
```

### Step 2: Verify the Instance Before the Change

Before modifying the instance, verify:

- **Instance state:** `Running`
- **Instance type:** `t2.micro`
- **Status checks:** Completed successfully

Wait if the status checks are still showing:

```text
Initializing
```

### Step 3: Stop the EC2 Instance

The instance must be stopped before changing its instance type.

1. Select `datacenter-ec2`.
2. Choose **Instance state → Stop instance**.
3. Confirm by clicking **Stop**.
4. Wait until the instance state becomes:

```text
Stopped
```

> Stopping an instance causes service downtime. In production, this change should be performed during an approved maintenance window or after traffic has been safely redirected.

### Step 4: Change the Instance Type

With the instance stopped:

1. Select `datacenter-ec2`.
2. Choose **Actions → Instance settings → Change instance type**.
3. Change the instance type from:

```text
t2.micro
```

to:

```text
t2.nano
```

4. Click **Apply**.

### Step 5: Start the EC2 Instance

1. Select `datacenter-ec2`.
2. Choose **Instance state → Start instance**.
3. Wait until the instance returns to:

```text
Running
```

### Step 6: Wait for Status Checks

After the instance starts, allow AWS to complete its health checks.

Wait until the EC2 console reports:

```text
2/2 checks passed
```

## Validation

Select `datacenter-ec2` and verify:

```text
Instance Name:    datacenter-ec2
Instance Type:    t2.nano
Instance State:   Running
Status Checks:    2/2 checks passed
Region:           us-east-1
```

The original success criteria have now been satisfied:

- The instance type changed from `t2.micro` to `t2.nano`.
- The EC2 instance returned to the `Running` state.
- AWS status checks completed successfully.

## Result

✅ `datacenter-ec2` successfully stopped before modification.

✅ Instance type changed from `t2.micro` to `t2.nano`.

✅ EC2 instance successfully restarted.

✅ Instance returned to the `Running` state.

✅ Status checks verified after the change.

## Key Takeaway

Changing the instance type is a common method of **right-sizing** EC2 workloads.

The basic dependency path is:

```text
Running EC2
     ↓
Verify Health
     ↓
Stop Instance
     ↓
Change Instance Type
     ↓
Start Instance
     ↓
Verify Health
```

The important production consideration is **downtime**. For a standalone EC2 instance, changing the instance type generally requires stopping the instance first. Before performing this operation in production, evaluate application availability, maintenance windows, dependencies, and rollback options.
