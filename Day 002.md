# 100 Days of Cloud AWS - Day 002: Create Security Group via AWS CLI

## Scenario

The Nautilus DevOps team is continuing the incremental migration of its infrastructure to AWS. For this task, a security group is required in the **default VPC** to control inbound access to the Nautilus application servers.

## Requirement

Create an AWS Security Group with the following configuration:

- **Security Group Name:** `nautilus-sg`
- **Description:** `Security group for Nautilus App Servers`
- **VPC:** Default VPC
- **Region:** `us-east-1`
- **Inbound HTTP:** TCP port `80` from `0.0.0.0/0`
- **Inbound SSH:** TCP port `22` from `0.0.0.0/0`

## Implementation

First, retrieve the default VPC ID:

```bash
VPC_ID=$(aws ec2 describe-vpcs \
  --filters "Name=is-default,Values=true" \
  --query "Vpcs[0].VpcId" \
  --output text)
```

Verify the retrieved VPC:

```bash
echo $VPC_ID
```

Create the security group inside the default VPC:

```bash
SG_ID=$(aws ec2 create-security-group \
  --group-name nautilus-sg \
  --description "Security group for Nautilus App Servers" \
  --vpc-id $VPC_ID \
  --query "GroupId" \
  --output text)
```

Verify the security group ID:

```bash
echo $SG_ID
```

Add the HTTP inbound rule:

```bash
aws ec2 authorize-security-group-ingress \
  --group-id $SG_ID \
  --protocol tcp \
  --port 80 \
  --cidr 0.0.0.0/0
```

Add the SSH inbound rule:

```bash
aws ec2 authorize-security-group-ingress \
  --group-id $SG_ID \
  --protocol tcp \
  --port 22 \
  --cidr 0.0.0.0/0
```

## Validation

Verify the security group configuration:

```bash
aws ec2 describe-security-groups \
  --group-ids $SG_ID \
  --query "SecurityGroups[*].{Name:GroupName,Description:Description,VpcId:VpcId,InboundRules:IpPermissions}" \
  --output json
```

The security group should contain:

```text
HTTP    TCP    80    0.0.0.0/0
SSH     TCP    22    0.0.0.0/0
```

## Result

✅ Security group `nautilus-sg` successfully created.

✅ Security group created inside the default VPC.

✅ HTTP port `80` allowed from `0.0.0.0/0`.

✅ SSH port `22` allowed from `0.0.0.0/0`.

✅ Challenge successfully completed and validated.

## Key Takeaway

AWS Security Groups act as **stateful virtual firewalls** for AWS resources. Inbound rules determine which traffic is permitted to reach resources associated with the security group.

Although this lab requires SSH access from:

```text
0.0.0.0/0
```

this exposes port `22` to the entire internet. In a production environment, SSH should normally be restricted to trusted administrative networks or avoided entirely by using services such as **AWS Systems Manager Session Manager**.
