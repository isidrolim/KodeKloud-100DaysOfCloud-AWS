# 100 Days of Cloud AWS - Day 005: Create GP3 Volume

## Scenario

The Nautilus DevOps team is continuing its incremental migration to AWS. For this task, an Amazon EBS volume needs to be provisioned for future storage requirements.

## Requirement

Create an EBS volume with the following configuration:

- **Name:** `devops-volume`
- **Volume Type:** `gp3`
- **Size:** `2 GiB`
- **Region:** `us-east-1`

## Implementation

### Step 1: Open the EC2 Console

1. Sign in to the **AWS Management Console**.
2. Make sure the selected region is **N. Virginia (`us-east-1`)**.
3. Search for and open **EC2**.
4. From the left navigation pane, go to:
   - **Elastic Block Store**
   - **Volumes**
5. Click **Create volume**.

### Step 2: Configure the Volume

Set the following:

- **Volume type:** `General Purpose SSD (gp3)`
- **Size:** `2 GiB`

Leave the remaining settings at their defaults unless specified by the challenge.

> **Note:** An EBS volume is created in a specific Availability Zone. If it later needs to be attached to an EC2 instance, both the instance and volume must be in the **same Availability Zone**.

### Step 3: Add the Name Tag

Under **Tags**, click **Add tag** and configure:

- **Key:** `Name`
- **Value:** `devops-volume`

### Step 4: Create the Volume

1. Review the configuration.
2. Click **Create volume**.
3. Return to **EC2 → Elastic Block Store → Volumes**.

## Validation

Locate `devops-volume` and verify:

- **Name:** `devops-volume`
- **Type:** `gp3`
- **Size:** `2 GiB`
- **State:** `Available`

## Result

✅ EBS volume `devops-volume` created successfully.

✅ Volume type configured as `gp3`.

✅ Volume size configured as `2 GiB`.

✅ Volume is in the `Available` state and ready to be attached to an EC2 instance.

## Key Takeaway

Amazon EBS provides persistent block storage for EC2 instances.

A `gp3` volume allows storage capacity and performance to be configured independently and is a common general-purpose EBS volume type.

Also remember:

**EBS volumes are Availability Zone-specific.**

An EBS volume can only be directly attached to an EC2 instance located in the **same Availability Zone**.
