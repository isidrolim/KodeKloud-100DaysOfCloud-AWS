# 100 Days of Cloud AWS - Day 016: Create IAM User

## Scenario

The Nautilus DevOps team is configuring **AWS Identity and Access Management (IAM)** as part of its AWS infrastructure setup.

IAM provides centralized control over identities and permissions within an AWS account. For this task, a new IAM user needs to be created for future access management requirements.

## Requirement

Create an IAM user with the following configuration:

- **IAM User Name:** `iamuser_jim`
- No additional permissions, groups, or access credentials are required for this task.

## Implementation

### Step 1: Open the IAM Console

1. Sign in to the **AWS Management Console**.
2. Search for:

```text
IAM
```

3. Open **Identity and Access Management (IAM)**.

> IAM is a global AWS service, so IAM users are not tied to a specific AWS Region.

### Step 2: Navigate to IAM Users

From the IAM navigation pane, select:

```text
Access management → Users
```

Click:

```text
Create user
```

### Step 3: Configure the User

Enter the required username:

```text
iamuser_jim
```

For this challenge, only the IAM user itself is required.

Do not configure additional console access, permissions, groups, or policies unless specifically requested by the task.

Click:

```text
Next
```

### Step 4: Configure Permissions

Since the challenge only requires creation of the IAM user, do not assign additional permissions.

Continue to the review page.

### Step 5: Create the User

Review the configuration:

```text
User name: iamuser_jim
```

Click:

```text
Create user
```

## Validation

Navigate to:

```text
IAM → Users
```

Verify that the following user exists:

```text
iamuser_jim
```

Select the user and confirm:

```text
User name: iamuser_jim
```

The original success criteria are satisfied when the IAM user exists successfully.

## Result

✅ IAM service accessed successfully.

✅ IAM user `iamuser_jim` created.

✅ No unnecessary permissions were assigned.

✅ User existence verified from the IAM console.

✅ Challenge successfully completed and validated.

## Key Takeaway

An **IAM user** represents an identity within an AWS account that can be granted permissions to interact with AWS resources.

The basic IAM authorization relationship can be visualized as:

```text
IAM Identity
     │
     ▼
IAM Policy
     │
     ▼
Permissions
     │
     ▼
AWS Resources
```

Creating an IAM user by itself does **not** automatically grant that user access to AWS resources. Permissions must be explicitly granted through IAM policies, either directly or through mechanisms such as IAM groups.

A core production principle is:

```text
Least Privilege
      │
      ▼
Grant only the permissions
required to perform the job
```

Avoid assigning broad permissions simply for convenience. Start with the minimum required access and expand permissions only when there is a validated business or operational requirement.

For human access in modern AWS environments, also evaluate centralized and temporary credential approaches such as **AWS IAM Identity Center** rather than creating long-lived IAM user credentials unnecessarily.
